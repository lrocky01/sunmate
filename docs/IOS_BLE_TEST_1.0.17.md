# SunMate 1.0.17+18：设备资料、连接设置与原生诊断

## 本版用于什么

这版参考官方 APK 中确认的设备管理结构，在现有连接页补充账号设备资料和分层状态。系统连接逻辑、厂商鉴权协议、HAL 及私有 MOSS-ASR/Hermes 直连不变；**尚未证明解决 iPhone 的 connecting pending**。

账号设备页新增：SN、账号设备类型、MAC 字段是否返回、共享密钥可恢复/未返回/格式不匹配。只显示状态，不显示地址或密钥值。手机号登录只读设备列表；首次 /check 和 /bind 仍只在真实设备挑战/公钥交换后执行。

「录音卡设置与诊断」独立显示蓝牙链路、GATT 服务、设备身份、录音通道。通知授权属性、已有合法格式密钥、当前系统连接都不代替本次业务验证。未确认灯效/多击/OTA协议，因此不显示可操作的假设置。

## 对照顺序

1. **先在同一台 iPhone 测官方 App**：关闭 Android 蓝牙，登录同一账号，正常连接卡片，保持一分钟、操作录音按键。若提示解绑或重置，停在提示处。记录能否连接、按键是否响应。
2. 完成官方对照后，退出官方 App，安装本版，核对首页显示 **1.0.17+18**；保持 Android 蓝牙关闭。
3. 进入 SunMate 登录自己的官方账号，读取设备。记录目标设备的资料摘要，尤其共享密钥状态。验证码、会话和密钥不要发到聊天。
4. 点击「选择并搜索」，在「设备资料与连接方式」中可明确切换请求 iPhone 通知服务。该选项连接前选择、下次连接生效，不在失败时自动切换。连接扫描到的目标卡。
5. 如果失败，打开「查看并复制完整诊断日志」，或首页「录音卡设置与诊断」右上复制。保留包含 RequiresANCS=true/false 的整段记录，不只截最后几行。

## 新日志怎么看

- `connectable`：本次取得的扫描结果是否被系统标记为可连接。能扫描到名称不等于当前一定可发起连接。
- `scanAgeMs`、`rssi`：选择扫描结果时的时间差与信号。不是 HCI 抓包，不能据此单独判定射频或地址问题。
- `central`：CBCentralManager 状态（poweredOn=5）；`state`：当前 CBPeripheral 状态。
- `pending`：本插件的待连接记录，不等同于底层射频链路状态。
- `systemConnectedMatch`：目标 UUID 是否出现在 iOS 当前已连接的 HID/两个录音服务查询中。只返回目标布尔值，不导出其它外设。命中仍需 App 本地连接；未命中不能证明所有物理链路均不存在。
- `event=...` 是原生事件；`snapshot lastEvent=...` 是读取最后事件的当前状态快照，旧 nativeTime 重复不表示又发了一次连接。

若同一 iPhone 官方也连不上，优先查系统/卡片当前连接状态。若官方可以而 SunMate 不行，结合这些原生状态继续查 App 的接入差异。只有进入 GATT 后，再根据实际设备挑战、验机 HTTP/业务码、密钥协商和 AES 回执判断账号材料问题。不要仅因连接失败就解绑、忘记设备或恢复出厂。

本轮用户已经反馈同一 iPhone 官方 App 也失败，无需为此重复登录。当前下一步只读查看 iPhone 设置→蓝牙中的目标卡归属和连接状态；新版本保留用于进一步检查原生状态，不视为已修复系统连接。
