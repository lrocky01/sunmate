# 1.0.20+21：已绑定卡的账号密钥恢复

## 修复依据

用户在 Android 官方 App 用新账号重新绑定后，SunMate 账号页已显示“可恢复，仍需卡片验证”。这证明新账号返回了格式和协议可用的共享密钥材料，不代表卡片已验证它。

旧驱动只从业务事件取得 SN；早期身份挑战不含 SN 时，账号恢复被跳过，即使扫描日志已经包含完整真实 SN，仍可能发 bindRequest。离线回归使用同一模拟卡和账号密钥：事件带 SN 时原测试通过；只有广播带 SN、早期挑战不带 SN 时，新增成功断言在旧实现失败。不是根据 bindError 包长推断固件具体拒绝原因。

REA 核对官方2.2.2/2.3.0 的 Telink 广播解码，确认它从广播取得 SN，入口经 R8 合并为 io.ktor.events.Events.decode。2.3.0 的下游过滤/转换将其它厂商段作为 UTF-8 候选，未将其称作密码学验证。iOS 插件只去掉 CoreBluetooth 厂商数据前两个公司ID字节；用户日志中0x1c0d的20字节payload包含两字节状态、1d2c标记和16字节SN。

证据：2.2.2 `ev_3d9015d7846c1e63d72aede1554cb00ea9db1670b138757458c5d7a93ece46c4`；2.3.0 `ev_e4fb1ccd3d23a022a1f8dd0c524c0e9b32efa01355e5f71bb93bb09c603bd9ac`；过滤 `ev_57e51f730213e9fd671ed0c1039e9fa711b7b2eafc6b1117a8bfd4be56e5134c`；转换 `ev_5dd934156f52f6ffe33c33fac7e5b1e543dc46633978a9832c42c307d6c41bd2`。原始证据在忽略目录tools/ble_audit/runtime-official-20261018。

## 本版范围

- 仅接受已确认Telink厂商ID/广播版本、精确长度及完整ASCII SN；支持iOS组合布局及Android分段布局，拒绝截断、移位、冲突和非ASCII数据。不从蓝牙名称、账号所选SN或UUID编造硬件SN。
- 使用同一蓝牙remoteId最近30秒内的扫描记录，且实际完整GATT确认为Telink后，才采用广播SN。账号、先前设备记录及后续设备事件有冲突即停止。
- 已有可恢复账号材料时走恢复和真实AES挑战；匹配失败不转成新的bindRequest，不解绑、重置或重新协商，不覆盖不同旧key。
- 诊断区分SN来源。只有收到本次有效挑战应答后的success=true且事件/音频通道就绪，才报告“设备业务已验证”。HAL、写入通道、AES算法和私有MOSS-ASR/Hermes直连保留。

## 验证

本地90项测试全部通过。包括旧实现失败的新回归、错误账号/事件SN冲突/坏广播/其它外设/未知GATT拒绝、错误密钥被AES拒绝，以及现有首次协商、取消、旧密钥不覆盖和音频Ogg用例。静态分析无错误/警告，保留11条既有弃用info；diff检查通过。未在本地模拟测试中调用真实短信或厂商绑定接口。

上述是代码和模拟对端验证。真实卡片是否接受恢复密钥、能否长时间稳定录音，仍需本次iPhone测试，不提前宣布完成。

## 手机操作

1. 保留当前新账号绑定，不再解绑卡片。关闭Android蓝牙，然后开启iPhone蓝牙。
2. 沿用此前安装方式安装1.0.20+21，确认首页版本号。使用刚才显示“可恢复”的新账号，从“连接录音卡”入口登录、选设备、搜索C·ONE-4552并连接。
3. 预期诊断出现“已从真实厂商广播取得完整SN”“已恢复与实际SN和协议匹配的账号密钥”“verifyIdentityResult success=true”，最终“设备业务已验证”。这一路不应发送bindRequest。
4. 保持一分钟后，用卡片物理按键录一段普通测试语句，检查按下/松开、录音数据和私有ASR转写。连接与ASR分别验收。
5. 首次成功后再断开/重连，使用本机已验证身份重连入口核对免短信重连。不要通过退出官方账号、清数据或解绑来测试。

若未通过，复制1.0.20+21蓝牙诊断，保留“设备匹配SN及来源”、最近错误和从订阅事件开始的日志即可，不提供密钥、验证码或Token。系统配对框是否再次出现不是本次业务验证的验收条件，已有系统配对可能直接复用。
