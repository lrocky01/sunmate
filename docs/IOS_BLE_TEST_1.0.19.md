# SunMate 1.0.19+20：卡片拒绝原因与服务器字段诊断

本版补诊断，不改变绑定策略，不自动解绑或重置，不宣称解决了卡片的bindError。HAL、多驱动及私有MOSS-ASR/Hermes直连不变。完整设备页/接口来源对照见 [数据映射](IOS_BLE_ACCOUNT_DATA_MAP_2026-10-18.md)。

## 已知事实

上一版721ms连接、1558ms发现业务GATT，ANCS属性true；正常bindRequest后1736ms收到bindError。没有verifyRequest，不能解释成云/check鉴权失败。官方也在bindError时停止配对，错误详情取error/reason/message/status。原版日志漏记这些字段。

官方设备列表模型有4个一级字段，extInfo再含mac/sharedSecret/uuid，共6个叶子字段。SunMate均有对应读取，但尚不能由模型断定本账号实际完整响应结构，也未完全恢复官方所有设置页方法。

## 新诊断

- 蓝牙失败：记录error/reason/message/status/code的安全摘要，有限描述词和短数字状态码可见，未知文字、标识和凭据隐藏。不会复制整个响应或挑战。未知文字被隐藏不等于设备未返回字段，也不把描述词当执行解绑的指令。
- 蓝牙诊断头保留最近错误，不因清理后「已断开」而丢失拒绝摘要。
- 账号诊断：顶层/data/设备记录字段数量、前5条记录的已知字段缺失/null/空字符串/非空字符串类型，以及额外字段数量。未知字段名称和值不输出，MAC、UUID、密钥和值不输出。仍是原设备列表请求，不增加接口、短信或轮询。

## 手机步骤

1. 保留当前配对，不解绑或重置；退出官方App，Android蓝牙保持关闭。
2. 安装并核对1.0.19+20；在SunMate登录同一账号、读取设备后，复制「账号诊断（不含凭据）」。本次重新登录用于本包读取实际响应结构，不是把登录当作已确定的修复。
3. 正常选择目标卡连接一次。若仍bindError，复制完整蓝牙诊断，关注「拒绝详情（安全摘要）」。
4. 把两份诊断发回，不发送手机号、验证码、Token、签名或密钥。即使出现already_bound文字，也先保留绑定，不重复解绑/重置。
