# SunMate 1.0.13+14 手机测试

本版增加正常官方账号登录、既有绑定恢复，以及本地身份挑战与物理按键实时 Ogg/Opus 录音。1.0.12+13 只保留过本地源码，没有发安装包。HAL 和私有 MOSS-ASR / Hermes 端点保持原有架构。

## 恢复已有绑定

1. 保留官方 App 和卡的现有绑定，不恢复出厂、不解绑。暂时退出官方 App，避免抢占蓝牙连接。按此前自签名方式安装新 IPA，确认首页显示 1.0.13+14。
2. 首页连接一次 C·ONE-4552，让 SunMate 收到设备事件及真实 SN。没有共享密钥时仍可能数秒后断开，这是恢复前的预期现象。
3. 打开“蓝牙状态与诊断日志”，进入“通过自己的官方账号恢复设备绑定”。网络保持可用，在手机本页输入自己的官方账号手机号和短信验证码；不要把验证码、会话或密钥发到聊天。
4. 页面读取自己账号的设备列表。只有 SN 和协议与当前卡同时匹配才允许“恢复并验证连接”。恢复后自动重连；仅设备返回本次 `verifyIdentityResult.success=true` 且通知通道准备完毕，才显示连接成功。

官网的验证码入口使用 channel=6，Android App 使用 channel=3。已核实两侧客户端契约，尚未验证后端是否允许该会话读取 App 的设备记录。如果显示权限不足、无设备或无完整恢复材料，请原样提供页面的脱敏提示以及蓝牙诊断；不能据此直接断言必须购买 SDK。登录会话只在页面内存中使用，关闭清除；确认恢复的共享密钥进入系统安全存储。已有不同本地密钥不自动覆盖。

## 验证连接和录音

1. 成功后保持前台连接至少 10 分钟；再断开、重连，并关闭重开 App 测试已保存设备恢复。无需反复看到系统弹窗，已有 bond 和 ANCS 授权可能被 iOS 复用。
2. 保持蓝牙开启，关闭手机 Wi-Fi 和蜂窝数据，验证仍能本地鉴权重连及收到物理按键事件。此时私有端点可能不可达，不能用 ASR 失败判断蓝牙失败。
3. 恢复私有服务网络，长按卡片说一句话后松开，检查完整会话经 Ogg/Opus 提交私有 MOSS-ASR，随后使用原 Hermes 路径。中途取消或断线不应上传残缺录音。
4. 另测切后台再回来。记录版本、是否取得匹配设备、鉴权结果、持续时间、按键/音频结果及最后约 20 行蓝牙诊断。不要提供任何原始密钥、验证码或鉴权负载。

Telink 的 App 主动开始/暂停/恢复录音没有已核实的通用指令，本版仍使用卡片物理按键。长录音文件下载和 AiNote6095 音频不在本次实机验证范围。整个实体目标必须等上述手机结果通过后才算完成。
