# SunMate 1.0.23+24 iOS首次配对字段修复

## 本次改动

- iOS/Telink的真实厂商验机应答verifyResult增加JSON整数字段`isIos: 1`；Android继续省略。依据同一iPhone官方成功连接的实测报文，不把整数改为布尔或字符串。
- 保留真实厂商验机、X25519交换、系统安全存储、云同步及受控重连AES挑战；不将bindResult或ATT写入完成当作业务成功。
- 已有密钥保护、HAL多驱动、私有MOSS-ASR/Hermes端点及既有无响应写策略保持。没有新增自动解绑、清系统配对、恢复出厂或覆盖旧密钥动作。
- pubspec、首页、录音卡设置、诊断及诊断版本回归统一1.0.23+24；不改其它初始化参数或通知订阅。

## 系统弹窗的验收边界

官方成功样本在带isIos=1的verifyResult后，卡片主动发送SMP Security Request，iPhone完成配对和加密后才收到pairingResult。这次仅出现蓝牙配对框；报文同时存在卡片订阅iPhone ANCS的操作。

修复是对齐该平台字段，不提供强制弹框API。若这台iPhone与卡片已有有效系统配对，连接可以直接复用；若已有通知授权，也可能不再出现通知授权框。**不要求两个弹窗每次重现**，不为弹窗清配对或解绑。业务就绪、真实挑战成功和录音转写才是验收目标。尚未将本次本地测试等同实体成功。

## 手机测试步骤

1. 沿用此前个人自签方式，以相同签名覆盖安装，确认首页和诊断均为1.0.23+24；保留原App数据、安全存储和正常系统配对。
2. 关闭Android蓝牙，退出iPhone官方App，让卡片只连接SunMate。保留当前官方账号和卡片绑定。
3. 优先使用已保存登录、重新读取账号设备列表。若目标显示可恢复，选择该卡进行已有设备恢复和真实身份验证；不要为测试新字段主动解绑。此路径不一定发送首次verifyResult，也不一定再弹系统配对框。
4. 只有账号确实暂无该卡、本机也没有旧密钥时，才从「添加新录音卡」走首次流程。需要首次配对模式时按已实测的连续点击5次、蓝灯闪烁操作，再新鲜扫描连接。正常确认实际出现的配对/通知弹窗，不重复切换配对状态。
5. 若提示已有不同旧密钥、设备/SN不匹配或要求解绑/重置，停止并保留诊断；不清卡、不覆写密钥。
6. 业务验证成功后保持连接5分钟，再用卡片按键录一小段话，确认私有ASR转写和按键结束录音均正常。随后正常断开重连，检查能否复用密钥。
7. 若失败，提供本版蓝牙诊断及脱敏账号诊断，说明是否出现配对框/通知框；不发送手机号、验证码、Token、密钥或原始HCI。不能仅根据没有弹窗判断失败。
