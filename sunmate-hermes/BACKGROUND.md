# 会议与随身记录后台处理 · Hermes 2.3.0 / App 1.0.34+35

本版新增会议和随身记录的原生后台收段、文件上传、服务器私有 ASR / 自动总结及前台结果取回。手机和服务器新增开关均默认关闭；安装包不会代为部署、修改真实配置或操作卡片。完整安装顺序见 README.md。

## 数据流与开关

```mermaid
flowchart LR
  A[录音卡关闭分段] --> B[同一 CoreBluetooth 连接\n本次真实 AES 已确认]
  B --> C[原生收段\nOPS 大小/结构/SHA校验]
  C --> D[本机 Ogg 封装\n保留前段解码上下文]
  D --> E[文件型 URLSession 上传\nWi-Fi默认/蜂窝另选]
  E --> F[Hermes 同一私有入口\n音频事务回执/持久任务]
  F --> G[服务器解码/私有 ASR]
  G --> H[逐段文字与来源归档]
  H --> I[停止/尾段/连续目录确认后\n会议纪要或本次随身复盘]
  I --> J[增量取回本机\n会议整场/随身时间线]
```

入口：设置 → 私有资料同步 → **后台录音与服务器处理**。

以下新增开关全部默认关闭，不改既有前台 ASR / 自动纪要设置：

- 后台蓝牙收段；蜂窝网络上传许可。
- 会议：音频自动上传、服务器自动 ASR、完整归档后自动纪要。
- 随身记录：音频自动上传、服务器自动 ASR、本次录音结束后自动复盘。

ASR 依赖上传，总结依赖 ASR。关闭上游会一起关闭依赖。会话开始时固定用途、策略快照、服务器资料库和处理归属；后开启不自动补传历史，也不接管既有手机 ASR 任务。关闭当前开关暂停该类新工作及待传任务，已经发出的外部请求无法撤回。关闭通知来源/隐藏资料的服务器生效仍取决于可见性同步。

音频上传和模型处理分开：服务器处理未启用时可接收音频，但 ASR / 总结等待管理员配置。手机原有实时对讲、鉴权、密钥库、HAL 和私有节点配置保持原路径。

## 原生收段和 iOS 边界

- 扩展当前 vendor 插件的同一 `CBCentralManager`，不用第二个管理器、连接或假鉴权。后台交接必须绑定当前原生连接 epoch，且由 Dart 已完成真实 AES 的连接发起；断连、系统恢复均撤销原生收段资格，不能拿上次验证当本次鉴权。
- Flutter 停止新文件命令，等待当前事务完成后才交给原生；恢复时反向交接。没有协议取消/偏移续传指令，超时后隔离旧通道并要求普通重连、真实验证。已提交分段保留，未完成段不当成功。
- 活跃录音只读有关闭证明的分段。状态/段关闭通知触发增量目录；停止后连续目录补扫确认尾段，不下载正在写入的段，不发送删除命令。
- 源 OPS、封装 Ogg、本机整场与结果分别保存。OPS 每包小端长度/保留字段、实际大小、Opus 时长与 SHA 校验；Ogg 包含前段约一秒解码上下文，ASR 结果回填时按 lead48 裁去重叠，位置按累计样本定位。
- 原生收段日记与上传任务落盘，恢复前先核对 SHA / 来源版本 / 本次用途和资料库。导回前台后完成本机分段索引、整场封装和实际 CoreAudio 解码，再显示整场可播放。
- 新后台文件目录使用首次解锁后可访问的 iOS 文件保护；上传配置使用独立 Keychain 条目，卡片密钥不进入上传配置。文件型后台 URLSession 只带单段、限定大小与 SHA、有限有效期的上传票据。归档长期凭据不放入上传任务头。
- 第一次启用状态恢复需下次正常启动，复用插件原有恢复标识。系统恢复后仍需当前真实 AES，不能保证 Flutter 被系统重启后一定能在后台完成重新鉴权。
- `bluetooth-central` 只提供事件唤醒与有限执行机会，定时器不能使 App 永久驻留；文件传输和封装仍可能被系统延后。用户划掉 App 会中断系统上传，需要重新打开恢复。服务器已经收妥的音频可独立继续处理，尚在卡片/手机的数据不能凭服务器获取。
- 后台 URLSession 的重定向由系统处理，私有上传入口应直接到达、不返回重定向。票据无法用于聊天、读取其它资料或上传其它文件。

## 同一 Hermes 入口的新增协议

使用现有独立同步凭据、固定 profile 和 `serverId/libraryId`，不接官方 Relay，不开新监听端口。原有 `/ingest`、`/receipts`、四个只读工具保留。`rawAudio=false` 仍指旧文字 ingest；新音频单独走 `sunmate.audio.v1`。

| 路径（均在 `/sunmate/v1/audio`） | 用途 |
| --- | --- |
| `POST /policy` | 单调策略版本，默认无任何音频许可；核对依赖与当前服务器开关 |
| `POST /tickets` | 固定会话/分段/源 SHA/上下文 SHA/音频 SHA/字节/用途/时间证据，先查已有回执 |
| `PUT /upload/{id}` | 限单任务票据，流式写入临时文件，最终大小/SHA 符合并提交后确认 |
| `POST /manifest` | 停止、尾段确认、从 0 连续的精确来源清单；冲突保留，不猜完整 |
| `POST /results` | 认证客户端自己的递增游标分页，先安全保存结果再推进游标 |

SQLite 音频任务库和文件在当前 profile 的 `sunmate-archive/`，原文字库不迁移。相同来源、上下文及音频版本复用同一任务；重复上传先核回执。策略停用、客户端撤销在每次提交/工作循环重新检查。

服务器工作循环挂到原生 aiohttp 生命周期：没有额外 daemon 或部署动作。先持久记录提交意图，再请求 ASR；已知任务号恢复 GET 轮询。POST 结果不明标为 `submission_unknown`，不会盲目重发。纯本地解码/磁盘问题为 `preparation_paused`，保留原档并可安全重试准备。总结的提交不确定同样保留，不自动重复调用模型。

只有精确完整清单和全部转写就绪才自动总结。长输入分批保存中间证据，重启复用已完成批次，再生成正式结果；输入、单结果和容量均有边界，不完整时不能报告完整纪要。随身复盘只使用同客户端、当前可见、在已定位时间范围内的已同步通知；绝对时间未知时不强行融合。最终提交前再次检查通知来源可见性。

转写/正式结果立即进入同一归档库供 Hermes 查询。取回手机时按源 SHA、上下文、样本和偏移核对；既有不同结果不覆盖。再次同步保留服务器原资料 ID / 正文，查询可用引用，避免另建一份相同转写/总结。原文件不会自动删除。

默认服务器音频预留上限 2 GiB，单音频上限 256 MiB；手机空间不足停止收段，服务器 WAV 准备前预估空间。ASR 响应、结果分页和本机记录均有大小边界。到达边界保留原录音，不能靠删除原档腾空间。

## 管理员安装后显式配置

本版增加 `archive_runtime/audio_jobs.py`。使用完整 2.3.0 安装包，按 README.md 先保留旧插件、再准备新插件；保留现有资料库、配置及客户端身份。不要只替换清单或重新初始化已有库。

管理员在目标 profile 已有 `sunmate-archive/config.json` 中增加 `audioProcessing`，保留原有身份和客户端凭据。示例字段如下，**不是自动执行命令**：

```json
{
  "audioProcessing": {
    "enabled": false,
    "asrUrl": "https://自己的私有ASR入口",
    "asrTokenFile": "/绝对路径/私有ASR凭据文件",
    "hermesUrl": "http://127.0.0.1:对应profile端口",
    "hermesTokenFile": "/绝对路径/当前Hermes原生API凭据文件",
    "ffmpeg": "/绝对路径/ffmpeg"
  }
}
```

无 ASR Token 的私网服务可不填 `asrTokenFile`。凭据文件必须是普通文件、权限0600；不在聊天、日志或手机任务中传递。管理员确认正确私有端点及 profile 后才把 `enabled` 设为 true。服务器需现有 aiohttp 和可用的 ffmpeg；不自动安装依赖、改原配置或重启服务。
