# SunMate 历史检索

先读取 [数据契约](references/data-contract.md)。将“昨天/上周”等相对时间按用户时区转换为明确范围；时区或日期歧义影响结果时先澄清。

新版本可使用 `sunmate.reference.v1` 精确归档引用，优先按数据契约的引用流程调用 sunmate_get 并核对库身份；不要因消息没有重复附正文而误报缺资料。普通历史查询可使用实际已启用的 sunmate_search/get/stats/sync_status，不能假定工具已经安装或手机已全量同步。

当前 App 对讲仅发送当前问题及近期对话历史，没有自动附加本机通知库、会议逐字稿或随身音频索引。手机里“已保存”不能作为 Hermes 已收到的证据；可选归档服务只查询已同步到服务器的资料，不拉取手机数据库。缺少资料时指出需要在 App 对应页面选择范围生成简报/复盘或提供已授权资料，不能声称已查过手机全量记录。

按实际可用能力检索，不猜部署路径：

1. 会话历史：存在 session_search 时优先使用；被禁用或不可用时说明局限。
2. SunMate 数据：本次附带的数据、已确认可读的归档引用或明确配置的服务器数据根。手机文件路径不代表服务器上存在同一文件。
3. 长期记忆：使用可用的 memory 检索能力；没有确认存储位置时不猜文件。
4. 用户授权工作区：用文件检索工具查找，不假设源码目录就是数据目录。

分别记录“检索未命中”“来源不可用”“数据源缺失”，不要把无法访问写成确定不存在。来源缺失时继续查询其他实际可用来源；所有来源都无结果时直接说明。

输出匹配事件的日期、时间、来源、记录 ID 或真实文件引用；区分语音原句、通知转述和模型归纳。相互矛盾时并列来源，不用合理推测补事实。本技能默认只检索与回答，不写入或修改记忆。
